How to plan an AI agent pilot for a small business

Start with one job whose output you can check. Write the input, expected result and approval limits before testing it.

Inferred method: the procedure and fictional pilot below are suggested planning steps. They are not a tested deployment.

Choose a job with a clear end

Pick one repeatable task. Keep work that needs judgment with its current owner. Avoid a first pilot that sends messages or changes accounts.

For this example, the job is to draft a link-check note for a resource page. The owner reviews the note before changing anything.

Write a pilot brief before choosing tools

Copy this fictional brief into a text file. Replace the sample scope with your own approved task.

Job: Draft a resource-page check note.
Owner: The person responsible for the page.
Input: An approved public page and its linked PDF and offer.
Output: A Markdown note listing each URL, HTTP status,
        page observations and any checks still needed.
Allowed: Read the approved public URLs and write a local draft.
Approval required: Every site edit or outbound message.
Stop: Login, challenge, 403, rate limit or unapproved URL.
Finish: Owner compares the note with the source pages.

Keep the first input small. Use public or fictional material. Keep client records and credentials out of this exercise.

Define pass and stop conditions

Before running the pilot, write the checks you will apply to its output.

CheckPass condition for this example
ScopeThe note covers only the approved page, PDF and offer.
EvidenceEvery reported HTTP status comes from a recorded GET.
AccuracyThe note records disabled signup and does not claim email delivery works.
ApprovalThe run produces a local draft without publishing changes or submitting forms.
Stop handlingA challenge or restricted response appears as an untested item, without a bypass.

Keep the first run manual

Compare each line with the source. Record the input, instruction version, output and your pass or fail decision.

If the draft invents a status, tighten the evidence rule. Repeat the same input before expanding the scope.
